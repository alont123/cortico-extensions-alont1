# 扩展协作第一步：图片附件进入作品页

当前源码实现了一条可选链路：**来源工具返回附件 → 模型按当前意图选择收录 → 作品页通过宿主读取附件并保存副本**。本仓 npm 版本仍是发布基线；本页介绍源码新增能力，尚不代表 npm 上已有该工具。

## 单独装和一起装分别能做什么

| 安装组合 | 可以做什么 | 缺少配套扩展时 |
|---|---|---|
| 仅作品页 | 标题、备注、本地文件收录；生成本地 HTML 页 | 所有原工具保持可用 |
| 作品页 + 相册 | 从相册翻出图片，用回执中的句柄收进作品页 | 不装相册时仍可使用其他已有附件或本地文件 |
| 作品页 + 能返回图片附件的 World | 可将取得的图片按句柄收录 | 不要求具体来源扩展名，来源工具不在场就不调用它 |
| 仅相册/生图等来源扩展 | 保持原本的浏览或生成能力 | 不需要作品页，也不会自动安装它 |

这里的协作使用 Cortico 已有 `WorldHost.blob` 与工具回执协议，没有新增 World 间调用接口、后台转发服务或全局共享数据库。Persona/模型通过实际可用的工具列表判断能否继续，由 Core 按普通工具流程派发。数据始终由各自扩展管理。

## 跟做一次

1. 先启用作品页，确认当前工具列表中有 `works_import_image`。没有这个工具时，说明尚未加载含此修改的源码版本，使用 `works_add` 原路径即可。
2. 让当前可用的图片工具返回一张图片。使用相册时，先 `album_list` 获取条目 id，再 `album_view` 查看；回执附件提供 `log:…` 或 `mem:…` 句柄。
3. 调用 `works_import_image`，参数是 `handle`、`title` 和可选 `note`。`handle` 必须复制实际回执值，不自己拼哈希，也不要填相册 id。测试夹具的句柄不是生产可用图片。
4. 返回“已收录附件 #…”后，用 `works_list` 核对标题与来源，再 `works_page` 生成本地页面。生成本地页不等于上传或发给别人。
5. 对同一句柄再调用一次，应返回“已收录…未重复保存或修改”。重载作品页后重复操作也不会多出同一句柄的条目。

模型可以根据当前任务不收录，也可以先确认要保留哪张。原图中的文字、标题和备注都是素材，不会因跨工具传递获得 `internal` 指令权限。实现本身不新建事件，因此不形成事件回环。

## 边界与失败结果

- **格式**：只接收 PNG、JPEG、GIF、WebP；MIME 和文件头需要一致；0 字节、超过 20 MiB、SVG 和网页内容返回失败。文件头检查不证明图片完整可解码，也不判断内容是否适合公开。
- **来源**：输入只交给当前 World 的宿主 `blob()` 能力。作品页不解析 `mem:` 的后端路径、不打开其他 World 的数据库；源句柄与 SHA-256 进入自己的索引。
- **能力缺失**：宿主无 `blob()`、扩展尚未启动或已经停止时返回明确失败，原有 `works_add` 可继续独立使用。未知句柄协议不会退回任意路径读取。
- **来源清理**：导入前已失效的附件不创建条目。导入后清理来源附件不影响作品页副本；作品页副本损坏或丢失需要自己的备份恢复。
- **重试**：按完整输入句柄去重；重试不更新标题、备注或文件。不自动归并不同句柄指向的同内容图片，避免丢失来源区别。
- **持久化**：先创建不覆盖既有文件的新副本，再原子替换索引。索引保存失败会清理本次新副本。进程被强制终止在这两步之间仍可能留下无索引的文件；本阶段没有后台垃圾回收。
- **隐私与发布**：本阶段只有本地导入，既不自动发 QQ，也不自动上传作品页。对外发送仍走相应 World 的工具和现有权限。

## 验证

在仓库根目录运行：

```powershell
node --import tsx --test tests/ecosystem/works-import.test.ts
```

测试使用真实 `AlbumWorld`、`WorksWorld`、`JsonlEventStore`、`LogBlobStore` 和临时磁盘文件；不启动真实 bot、不调用模型、不连接 QQ/生图服务。覆盖单装、联合、缺失来源、旧宿主能力不足、未知句柄协议、文件类型伪装、大小限制、重复/并发重试、重载、来源清理、保存失败和不新增转发事件。`mem:` 场景仅使用宿主解析函数夹具，不读取真实 Memory。

这些测试验证附件互通和持久化行为，不代表已经完成真实模型选择工具、全套扩展安装或直播体验验收。
