# Cortico 零基础入门手册

从“我不知道该点哪里”，到能安装一个扩展、看懂一次回复、独立描述一个故障。

2026-10-28 · 新手跟做版。电脑上可以边看边操作，手机上先读概念和例子。本文的源码核对基线是 Cortico 本地 0.2.0 快照及 alont1 扩展源码；不是对所有宿主版本的承诺。界面按钮名称有差异时，以你安装版本的提示为准。

## 先读这一页：不用一口气学完

你不需要先学完编程。先做三件事：认出自己打开的程序，找到正在使用的配置，确认一个功能是否真的运行。

**只想把现成程序用起来：** 第 1 课 → 第 3 课 → 第 5、6 课 → 第 8 课。

**想弄懂它为什么会回复：** 第 1、4、7 课。

**想自己写扩展：** 先完成上面两条，再做第 2、9、10 课。第 11 课是课堂复习和后续学习路线。

每课都有“做什么、看到什么算成功、卡住看哪里”。第一次只完成一个小目标。今天能装好并验证一个扩展，就已经完成了一次完整练习。

全文约定：`C:\CorticoLab` 是你自己新建的练习文件夹；`C:\CorticoLab\Cortico-main` 是放源码的示例位置。它们不是程序自带目录，不存在时不能直接照抄命令。所有人名、任务和消息示例都是虚构的。

## 第 1 课：先认清你手里的东西

**本课目标：** 不把程序、模型、扩展和数据当成同一件东西。

假设你希望一个角色在控制台跟你聊天，偶尔查看任务板。你会遇到下面这些名字：

| 名字 | 先用普通话理解 | 你会在哪里遇见它 |
|---|---|---|
| Coopanion / Coo | 用来启动、管理 bot 的桌面程序 | 桌面快捷方式、托盘、程序窗口 |
| Cortico | 让消息、模型、工具和运行状态配合工作的框架 | Coo 使用的 Core，或下载的源码目录 |
| 模型 | 根据收到的内容生成回答或提出工具调用的软件服务 | 模型端点设置 |
| 扩展 | 给宿主增加一种能力的代码包 | 扩展列表，例如任务板、天气 |
| 部署 | 某一个 bot 的配置与运行数据所在位置 | 部署选择、数据目录 |
| 控制台 / WebUI | 用网页操作程序的界面 | 浏览器里的本机地址 |

不要现在背英文。先记一个例子：**换模型**是在换生成回答的服务；**换扩展**是在换可用能力；**换部署**可能是在换另一份角色数据。它们不是同一个操作。

### 跟着做：辨认你的使用路线

1. 看你平时怎样启动。双击 Coo 图标就能进入的，走“桌面程序路线”。
2. 如果你有 `src`、`bots`、`package.json` 等文件，并通过命令启动，走“源码路线”。
3. 在纸上写下：我用的程序名、程序版本、当前部署的显示名称。找不到版本时，先写“待确认”，不要猜。

**成功标准：** 你能说出“我用 Coo 管理一个部署，给它安装任务板扩展，模型在端点设置里选择”。

**卡住时：** 如果文件夹里同时有多份 Coo、源码和备份，先确认平时使用的快捷方式指向哪里。不要因为另一个文件夹更新，就认为正在运行的程序也已更新。

**练习 1：** 我卸载了一个扩展，是否就等于删除了角色的全部记忆？先猜，再看文末答案。

## 第 2 课：看懂文件夹、路径和命令

**本课目标：** 知道命令在哪个文件夹执行，不因路径错误绕远路。只用桌面程序的读者也值得读前半课。

### 三个最常见的东西

**文件**保存内容，例如 `config.json`。**文件夹**装文件，例如 `C:\CorticoLab`。**路径**说明东西在哪里，例如 `C:\CorticoLab\sample.json`。

文件名后面的 `.json`、`.ts` 是扩展名。Windows 资源管理器中可以打开“文件扩展名”显示；Windows 11 通常在“查看 → 显示”里。这样不会把 `sample.json.txt` 误认成 JSON 文件。

**PowerShell**是输入命令的窗口。命令里的 `PS C:\...>` 是窗口提示符，不是让你复制的内容。本文代码框里只放需要输入的命令。

### 跟着做：只查看，不修改

从开始菜单打开 PowerShell，输入：

```powershell
Get-Location
```

它会显示当前文件夹。接着输入：

```powershell
Get-ChildItem
```

它会列出当前文件夹里的内容。两条命令都不会启动 bot。

如果你已在资源管理器中创建 `C:\CorticoLab`，输入：

```powershell
Set-Location -LiteralPath 'C:\CorticoLab'
```

再运行 `Get-Location`，结果应变成这个练习目录。单引号把路径包起来，文件夹名有空格时也能作为一个整体传入。

**看到什么算成功：** 你能进入自己创建的文件夹，并看见里面的文件。

**报“路径不存在”：** 回资源管理器确认路径，不要反复输入同一条命令。`C:\CorticoLab` 只是示例，不会自动出现。

**报“不是可识别的命令”：** 说明当前环境找不到那个程序，或命令拼错。它与“Cortico 代码写错”是两类问题。

### 以后看到这些命令，先知道用途

| 命令 | 用途 | 会不会启动实际 bot |
|---|---|---|
| `node --version` | 查看 JavaScript 运行环境版本 | 不会 |
| `pnpm --version` | 查看依赖安装工具版本 | 不会 |
| `pnpm install` | 下载项目声明的依赖，通常需要联网 | 不会直接启动 bot，但安装过程可能运行依赖的安装脚本 |
| `pnpm start` | 运行项目定义的启动命令 | 在 Cortico 主仓会 |
| `pnpm test` | 执行项目测试 | 本项目测试使用受控环境，不作为真实平台验收 |

初学时，每执行一条就看一次结果，不把一长串命令一起粘贴。错误出现后，从第一条错误开始看。

## 第 3 课：打开控制台，让最简单的对话先通

**本课目标：** 能打开正确部署的控制台，知道模型连接设置在哪里。下面是供你操作的步骤，本手册不会替你启动真实 bot。

### 路线 A：你已经安装了 Coo

如果你尚未安装 Coo，先从其发布者提供的可信发布页取得适合 Windows 的安装包，并按该版本安装说明完成安装。本手册没有核对 Coo 当前下载入口，因此不把同名搜索结果当成官方下载。也可以直接走下面有明确主仓地址的源码路线。不要把某个扩展的 ZIP 当作 Coo 安装包。

1. 用平时的快捷方式启动 Coo，确认当前部署名称。
2. 从程序提供的控制台入口打开网页。记下程序显示的实际地址，别把教程里的端口当成固定答案。
3. 在控制台找到模型端点设置。端点就是程序把请求交给模型服务的地址与配置。
4. 按你选择的服务提供方说明填写地址、模型标识和密钥。密钥是访问凭据，只填在程序的凭据设置中，不发到聊天或公开 issue。
5. 保存配置。回控制台对话页，只做一次简单问候，例如“你好，今天先试一下文字对话”。这一步可能消耗模型服务额度。
6. 查看是否出现回答，以及该次请求是否有明确错误。

**成功标准：** 控制台打开，正确部署收到这条输入，模型请求成功，并在控制台看见回答。

先不接 QQ、不加语音、不装一整套扩展。这样出问题时，你只需检查控制台和模型连接这两部分。

### 路线 B：你打算运行源码

源码是供运行环境执行的程序文件，不是下载后双击就能运行的安装包。还没有源码时，在浏览器打开主仓地址 `https://github.com/Pal-AI-Lab/Cortico`，确认页面上的仓库名是 `Pal-AI-Lab/Cortico`。在 Code 菜单中选择 Download ZIP；下载后右键 ZIP，使用“全部解压缩”，把解压结果放进自己建立的 `C:\CorticoLab`。不要在 ZIP 预览窗口里直接运行文件。

解压出的文件夹名称可能带分支名；本文统一用 `C:\CorticoLab\Cortico-main` 作为示例。若你的名字不同，下面路径也要随之替换。主分支会变化，本次核对的命令基于本文说明的快照；下载后优先核对该副本的 README 与 `package.json`。npm 上名为 `cortico` 的包主要提供扩展开发所需的框架源码契约，不能用“安装该 npm 包”替代这里的宿主安装和启动流程。

1. 在资源管理器确认这一层有 `package.json` 和 `bin`、`src` 文件夹。ZIP 解压后可能多包了一层文件夹，别在外层执行。
2. 在 PowerShell 进入它，并查看运行环境：

```powershell
Set-Location -LiteralPath 'C:\CorticoLab\Cortico-main'
node --version
```

本手册核对的版本要求 Node.js 22 或以上。Node.js 是执行 JavaScript 的程序。没有安装时，先通过 Node.js 官方安装程序安装受支持版本，再重新打开 PowerShell。

3. 检查 `package.json` 中的 `packageManager`。本次快照指定 `pnpm@11.5.0`，不同快照可能不同。若已有 Corepack，可按仓库说明执行 `corepack pnpm install`。若没有 Corepack、但 npm 已可用，可为本次快照安装指定 pnpm：

```powershell
npm install --global pnpm@11.5.0
pnpm.cmd --version
pnpm.cmd install
```

`pnpm.cmd` 是 Windows 下的命令入口；它可以避免把执行策略错误误当成包安装错误。这里不需要修改 PowerShell 执行策略。公司管理电脑如限制安装，应使用其允许的安装方式。

4. 依赖安装成功后，才运行：

```powershell
pnpm.cmd start
```

本地启动器会选择或建立部署，并显示 WebUI 地址。首次无部署的常见流程会建立 `mybot`；默认控制台地址是 `http://127.0.0.1:7788/`，实际以启动输出为准。若已有运行中的正式实例，不要再在同一份数据上启动第二份；练习请用单独的源码副本和新部署。

**成功标准：** 启动窗口持续运行，浏览器能打开它显示的控制台地址。此时模型未配置也不奇怪，继续完成路线 A 的端点设置。

**常见卡点：** “地址占用”先检查是否已有实例；浏览器打不开先看启动窗口有没有退出；依赖下载失败先处理下载错误，不跳过继续启动。

**练习 2：** 浏览器能打开控制台，但模型请求返回错误，说明本机网页服务一定没有启动吗？

## 第 4 课：一条消息到底经历了什么

**本课目标：** 不再把所有故障都叫“AI 不理我”。

我们用一句话走完整条路：**“请看看任务板里有没有没完成的事。”**

1. 你在控制台输入这句话。接收输入的模块把它交给运行系统。
2. 系统记录并安排处理。程序暂停时，收到输入与开始处理可能不是同一时刻。
3. 角色的运行逻辑准备这一轮给模型看的内容：有关的消息、当前可用工具、需要的角色信息。
4. 模型可能决定调用 `todo_list`，也可能先回答或询问；可用工具不等于每轮必用。
5. 系统把调用交给任务板扩展。扩展读取自己的任务数据，返回结果。
6. 模型根据结果组织回答，再通过相应输出通道把内容发出来。

这时再认识四个专有名词，就容易多了：

| 专有名词 | 在上面例子里做什么 | 不负责什么 |
|---|---|---|
| **World** | 接收某种环境输入、提供查看任务板或发消息等工具，并返回实际结果 | 不直接替角色决定内心想法，不直接写 Persona 的 Memory |
| **Core** | 安排处理、管理会话、派发工具调用、保存运行记录 | 不决定角色应该是什么性格 |
| **Persona** | 决定怎么组织角色上下文、如何使用和维护 Memory | 不应该把 QQ 等平台细节写进通用 Core |
| **Memory** | 保存这一个角色的长期内部状态，由 Persona 按自己的规则读写 | 不等于所有日志，也不等于所有扩展的文件 |

**Bot** 是把 Persona、Memory 和一组 World 组合起来的定义；**deployment（部署）**则保存某个实例实际使用的配置和数据。

### 用“办到哪一步”判断问题

模型说“我记住了”，不一定发生了保存。工具说“请求已发送”，不一定代表别人已读。判断成功要找对应证据：任务板查询结果、工具回执、平台上实际显示的消息。

**练习 3：** 对话中出现“已保存任务”，但没有任何 `todo_add` 的调用或其他持久化证据，你能确认任务已经写入吗？

## 第 5 课：配置是设置，JSON 只是写设置的一种方式

**本课目标：** 能看懂一小段配置，知道“已保存”和“正在生效”的区别。

普通用户优先用控制台表单修改设置。只有说明明确要求、并且你知道目标部署目录时，才手动编辑 `config.json`。

下面是**练习用示例**，不是让你覆盖正式配置的完整文件：

```json
{
  "worlds": {
    "clock": {
      "enabled": true,
      "announce": "off",
      "announceGapMinutes": 30
    }
  }
}
```

逐个读：`worlds` 是 World 配置所在的大项；`clock` 是时间扩展的标识；`enabled` 表示是否启用；`announce` 选 `off` 表示不主动报时；`announceGapMinutes` 的单位是分钟。

JSON 的五个基本规则：

1. 左右大括号 `{ }` 成对。
2. 属性名和文字用英文双引号，例如 `"announce"`。
3. `true`、`false` 是开关值，没有引号；`"false"` 是文字，意义不同。
4. 数字 `30` 不加引号。相邻项用英文逗号隔开，最后一项后面不加逗号。
5. 普通 JSON 不写 `// 注释`。说明文字放在文件外。

### 跟着做：保存一项，再验证一项

1. 在正确扩展的配置页记录原值，例如主动报时原来是 `quiet-hours`。
2. 改成希望的值，点击保存并等到保存成功。成功提示前不要立刻关页面。
3. 刷新页面，检查值是否仍是刚才的选择。
4. 看该项说明：写“热生效”的通常无需重启；写“重新挂载”或“重启”的，要完成对应操作。
5. 通过实际状态或一次明确的功能检查确认生效。

**三个操作不要混用：** 刷新网页只更新你看到的页面；重新挂载扩展会让该扩展停止后重新启动；重启 Core 会重建整个运行进程。重启 Coo 还涉及外层桌面程序。反馈问题时写清是哪一种。

**重要的开关区别：** 扩展卡片上的激活／停用负责启停；普通业务设置负责修改配置。在已修复的 alont1 面板中，不再用第二个根启用开关与宿主抢状态。配置里 `enabled` 的含义依然存在，但不建议新手同时手改它和点击界面开关。

**成功标准：** 刷新后配置还在；需要重载的项目完成重载后，功能表现与配置一致。

**练习 4：** 写着 `announceGapMinutes: 30`，为什么不能把它理解成 30 秒？

## 第 6 课：只装一个扩展，走完安装到验证

**本课目标：** 明白“安装了”“启用了”“能工作”是三次检查。

本课用任务板 `cortico-world-todo-alont1` 举例。它提供查看、新建、完成和删除任务的工具。本课先只查看，不动已有条目。

### 开始前准备

写下当前宿主版本、扩展完整包名、准备安装的版本。阅读它的说明，确认宿主兼容。若没有独立测试部署，先完成第 8 课备份；不要把正式角色的数据当练习草稿。

### 跟着做：图形界面路线

1. 打开控制台的扩展列表，选择 World 类别，在搜索或手动包名安装入口输入完整包名。
2. 核对作者、包名、版本和兼容提示，再安装。等待明确完成；下载完成但检查失败，不算安装成功。
3. 若界面显示“待重启”，保存手头工作后，按宿主提示重启。**磁盘上已有新版本，不等于当前进程已经加载它。**
4. 找到任务板对应的 World 卡片，通过宿主激活入口启用。确认状态已启用，且没有启动错误。
5. 打开配置页，先读页面上的中文使用教程。保留不理解的高级设置，只修改本次练习需要的项。
6. 在对话中说：“请使用任务板的 `todo_list` 查看未完成事项，不新增、完成或删除任务。”模型调用工具可能消耗额度。
7. 查看工具调用和回执。没有任务时，源码当前返回“没有没做完的事。”；有任务时应列出条目。文字回答本身不能替代工具回执。
8. 刷新控制台，确认启用状态仍在。再按宿主提供的方式重载扩展；如果该版本没有单独重载入口，就在方便时重启 Core。回来看启用状态和只读查询是否仍正常。

**成功标准：** 安装记录正确、实际运行状态启用、只读工具有回执、重载后状态保持。完成这四项，才开始增加第二个扩展。

### 仅给源码用户的命令行替代办法

图形界面能安装时，可以跳过本段。必须确认进入的是宿主实际使用的 `extensions` 文件夹；Coo 的数据目录可能另有位置，不能直接套用源码路径。

```powershell
Set-Location -LiteralPath 'C:\CorticoLab\Cortico-main\extensions'
pnpm.cmd add --ignore-workspace cortico-world-todo-alont1
```

`--ignore-workspace` 表示不要把这次部署扩展安装混进外层开发工作区。如果目标文件夹不存在，回到控制台安装流程，不要在不明位置新建一个同名文件夹然后继续。

### 三种故障，分别处理

**找不到包：** 检查完整包名和扩展市场网络，不要用相似名称替代。**提示 API 不兼容：** 对照宿主和扩展支持版本，不要只把清单里的数字改大。**激活后立刻关闭：** 查看此次激活报错，不要靠反复写 `enabled=true` 掩盖失败。

## 第 7 课：扩展怎么搭配，才不会越装越乱

**本课目标：** 能选择一组职责清楚的扩展，也知道互联应该改善什么。

先写需求，再选包。例如“我希望它能看任务、查天气”，就从任务板和天气两个功能开始；不必因为包都在同一个仓库就全部开启。

### 人味与七个独立扩展：二选一

当前 alont1 人味 `humanlike` 已内置下列功能：

| 独立扩展标识 | 功能 |
|---|---|
| `affinity` | 关系状态 |
| `learn` | 学习 |
| `life` | 作息与生活状态 |
| `clock` | 时间感 |
| `together` | 相处记录 |
| `mind` | 惦记与提醒 |
| `real` | 现实感知 |

**使用人味时，不要再同时启用这七个对应的独立扩展。** 这不是“功能越多越好”，重复运行可能重复提醒或维护两份状态。当前提示不会替你自动停用，也不会自动把两份数据合并。

如果只需要其中一种能力，可以选择对应独立扩展并停用人味。安装着但未启用，与正在运行，是不同状态。人味内部模块在当前修复版中随宿主总开关一起运行，不提供七个看似独立、实际上无效的子开关。

### 什么才算“单独可用，组合更顺手”

以任务板和天气为例：只装任务板，应仍能管理任务；只装天气，应仍能查天气；两者都装时，角色可以结合真实查询结果安排出门事项。

合理的协作过程是：模型根据现有工具选择查询 → 收到天气事实 → 结合你的请求决定是否记任务。**不能仅凭装了两包就自动声称能联动，也不能让一个扩展偷偷改另一个扩展的私有文件。** 自动联动必须有实际实现、可见规则和关闭办法。

你验收组合时问四件事：缺一包是否仍能正常运行？只读查询会不会意外发送消息？同一提醒会不会触发两遍？关闭联动后能否回到各自独立行为？

**练习 5：** 同时启用人味和独立时间扩展，是否必然让报时更准？

## 第 8 课：数据在哪里，备份要备什么

**本课目标：** 更新程序时保住数据，分享源码时不把私人数据带出去。

把运行目录分成两类看。**程序代码**描述“它会做什么”；**部署数据**描述“这一份实例配置了什么、积累了什么”。重新下载代码通常不能找回旧数据。

常见源码结构如下，具体位置由宿主配置决定：

```text
Cortico-main/
  src/                  框架程序
  bots/                 bot 类型的实现
  extensions/           当前宿主安装的外部扩展
  deployments/
    练习部署/
      deployment.json   选择哪种 bot
      config.json       这一份部署的配置
      workspace/        某些 Persona 使用的 Memory 目录
      ...               运行记录及各模块的数据
```

`workspace` 只是部分 Persona 的实现选择；Memory 不保证都叫这个名字。Coo 还可能把数据放在独立目录。**先从当前程序的配置或启动输出确认实际数据根目录。** 不要只凭某个目录名像“记忆”就认定它包含全部数据。

### 跟着做：一份可说明白的备份

1. 记录日期、宿主版本、扩展版本、实际部署目录。私人记录留在自己电脑，不放公开仓库。
2. 使用宿主提供的正常停止／关机入口，等运行结束。只关闭浏览器标签并没有停止后台程序。
3. 将确认过的完整部署数据复制到另一份带日期的备份目录；Coo 若有专用导出或备份说明，按它的范围操作。
4. 确认备份中保留相同的主要文件和目录结构。不要在未确认数据布局时只挑一两个 JSON。
5. 在独立测试位置验证恢复；不要直接覆盖仍在运行的原部署。数据库类文件和附属文件应作为整体处理。

**成功标准：** 你能说明备份对应哪个实例、哪个日期、哪个版本，以及恢复时应放回哪个数据根目录。只看到一个 ZIP 图标，还不等于已验证可恢复。

### Session 和 Memory 为什么不同

**Session（会话）**是一次持续处理过程所用的上下文与记录；**Memory**是由 Persona 维护的长期内部状态。上下文变长后可能做交接；交接不代表角色必须失忆，但也不代表每句闲聊都自动进入长期记忆。

工具查询的原始回执、模型生成的摘要、角色设定、真实发生的事情，要保留区别。摘要里写了一次“已经完成”，不能代替真实完成证据。

**公开分享清单：** 可以分享扩展源码、教程和合成测试；不要打包部署目录、真实对话、私人记忆、密钥、登录状态、`.env`、个人备份。

## 第 9 课：做一个离线实验，亲眼看懂配置与工具

**本课目标：** 不连接 QQ、不调用真实模型，也能观察一次确定的输入和结果。

### 实验 A：完全新手先检查 JSON

只需要安装了 Node.js。将本手册配套的 `exercises` 文件夹放到 `C:\CorticoLab\exercises`。里面有 `sample.json` 和 `read-config.mjs`。

```powershell
Set-Location -LiteralPath 'C:\CorticoLab\exercises'
node .\read-config.mjs
```

你应该看到：

```text
配置读取成功
功能已启用：true
示例问候：你好，先完成一个小练习。
提醒间隔（分钟）：30
```

现在用文本编辑器打开 `sample.json`，把 `greeting` 后面的文字改成自己的练习句，保存，再运行同一条命令。输出应随之改变。

最后，故意在副本里删掉一处双引号。再次运行，会收到“JSON 格式不正确”的提示。把引号补回，再次运行成功。这是在练习副本里观察错误，不是在修改正式配置。

**这验证了什么：** 程序读取文件、识别数据类型、使用配置值。**没有验证什么：** 它没有启动 Cortico、没有训练模型、没有把内容保存为角色记忆。

### 实验 B：实际运行 Cortico 的 World 模板测试

需要已经安装好依赖的独立 Cortico 源码副本。首次安装依赖可能联网；依赖备齐后的这组测试不需要模型、密钥或外部聊天平台。

在源码根目录运行：

```powershell
Set-Location -LiteralPath 'C:\CorticoLab\Cortico-main'
node node_modules/vitest/vitest.mjs run templates/extension/world/tests/world.test.ts
```

本次核对的快照应通过 **3 个测试**。它们实际检查：

1. 模板能按扩展契约被构造和检查。
2. 模板挂载时发出一条 `example.started` 事件，交给记录事件的假宿主。
3. 调用 `example_echo` 得到带配置问候的回执；修改问候配置后，回执随之变化。

“假宿主”是测试中记录事件的辅助对象。这里运行了真实 World 类和工具处理函数，但没有让真实模型决定调用，也没有对外发送消息。

**看到什么算成功：** 输出包含 `1 passed` 和 `3 passed`。本次编写手册时，这条命令已实际通过。

**提示找不到 vitest：** 先确认 `node_modules` 已安装，且当前目录确实是源码根。**提示找不到测试文件：** 说明你的源码版本或目录不同，先看模板的 README。不要为了凑出绿色结果创建一个同名空测试。

### 看一眼代码，不要求你立即会写

打开 `templates/extension/world/src/world.ts`，搜索 `example_echo`，再找 `handler`。`handler` 是实际处理工具调用的函数。它把配置里的问候与输入文字拼在一起返回。

这说明三件事：工具名字告诉调用方选哪个动作；参数告诉工具本次处理什么；回执告诉调用方实际得到了什么。**模型说一句“我调用了工具”，与代码真的执行 handler，是两回事。**

## 第 10 课：遇到故障，按顺序缩小范围

**本课目标：** 能提供别人看得懂、可以复现的问题描述。

先问“最后一个确定成功的步骤是什么”。不要同时换模型、更新十个扩展、重装宿主；那样即使恢复，也不知道哪个动作起作用。

| 你看见的现象 | 先检查什么 | 下一步保留什么证据 |
|---|---|---|
| 控制台打不开 | 程序是否仍运行，实际地址和端口是否正确 | 启动窗口最早的错误及时间 |
| 控制台正常但模型不回复 | 是否暂停，输入是否进入，模型请求是否报错 | 对应输入、请求错误，去除凭据 |
| 扩展安装失败 | 包名、版本、网络、兼容检查结果 | 完整包名和安装提示 |
| 扩展已安装但没有功能 | 是否实际启用，是否待重启，启动是否失败 | 卡片状态与加载版本 |
| 按钮点了没反应 | 是否需要先启用或保存，是否出现操作回执 | 按钮名称、操作前状态、错误提示 |
| 刷新后设置丢失 | 是否点过保存，是否保存到正确部署 | 保存提示和刷新前后值 |
| 重载后扩展关闭 | 当前磁盘启用状态、宿主激活结果、扩展版本 | 明确重载的是扩展、Core 还是整个 Coo |
| 同一句提醒出现两遍 | 是否启用了重复扩展、重复实例或重复订阅 | 两条提醒时间及启用列表 |
| AI 说办完，现实没有变化 | 是否真的调用工具，工具回执说了什么 | 调用名称、参数的非敏感部分、回执 |

### 可以直接复制的反馈格式

```text
我想完成：在重载后继续使用任务板。
宿主及版本：填写 Coo / Cortico 的实际版本。
扩展完整包名和版本：填写实际安装版本。
操作步骤：启用 → 保存某项设置 → 重载扩展。
预期结果：重载后仍启用，可查询任务。
实际结果：重载后卡片显示关闭。
发生时间：填写日期和时间。
第一条相关错误：粘贴已去除密钥和私人内容的原文。
最小复现：只开这个扩展时是否仍发生。
```

“报错了”是有用的起点，但“安装完成后，点击启用，等待约 30 秒，显示连接超时”能让维护者更快找到对应记录。看不到详细错误时，直接说明界面只有简短提示，不需要编造错误码。

### 准备写扩展时，再加这三项检查

先从官方 `templates/extension/world` 复制模板到独立练习目录。读模板 README，按其清单统一改包名、World 标识、工具前缀和配置路径；不要只改文件夹名。

在主仓根目录可运行 `pnpm.cmd check:extension <你的包目录>` 检查契约；尖括号部分要替换成实际目录，不是原样输入。检查会导入包代码，因此只检查你信任或正在开发的源码。

然后在扩展包自己的目录按其 `package.json` 运行测试与类型检查。类型检查像检查形状和接口；行为测试检查输入后是否得到正确结果；真实平台验收则确认外部服务是否可用。它们各自能证明的范围不同。

**本次快照提醒：** World / provider / bot 的当前契约号是 6 / 6 / 7；源码还有上一版过渡逻辑。旧说明里的数字可能落后，开发时看模板和 `src/extensions/manifest.ts`，不要凭手册里的数字强行改清单。本地 `package.json` 虽列出 `dev:console`，此次核对没有找到它对应的脚本，所以本文不把该命令列为新手必做步骤。

## 第 11 课：课堂复习、练习答案与下一步

### 十分钟复习卡

闭上前面的章节，试着完成这五句话：

1. 我现在用的宿主是 ______，正在使用的部署是 ______。
2. 当前扩展完整包名是 ______，安装与启用状态分别是 ______。
3. 这一项配置保存后，需要 ______ 才会生效。
4. 一次动作成功，我应检查 ______，而不只看角色说了什么。
5. 更新前，我备份了 ______，知道恢复位置是 ______。

能回答这五题，就已经具备日常使用和向别人描述故障的基础。

### 练习答案

**练习 1：** 不等于。扩展代码、扩展自己的运行数据、Persona 的 Memory 是不同东西；卸载后的数据处理还要看宿主和扩展说明。不能把“卸载扩展”当作已备份或已清空全部数据。

**练习 2：** 不是。控制台能打开说明网页服务至少能响应；模型服务连接、认证、模型标识或请求处理仍可能失败。

**练习 3：** 不能。需要对应的持久化动作与成功结果，并可通过后续查询确认。自然语言承诺不是落盘证据。

**练习 4：** 名字中的 `Minutes` 明确说明单位是分钟。改成 30 并不会变成每 30 秒触发。

**练习 5：** 不会。人味已有时间功能，重复启用可能增加重复状态和提醒，应选择一套。

### 从入门走向能独立修改

| 阶段 | 你要能做什么 | 推荐下一步 |
|---|---|---|
| 会使用 | 安装一个扩展、保存配置、验证重载后状态 | 重做第 6 课，留下自己的验收记录 |
| 会排查 | 沿着输入、模型请求、工具、回执定位中断位置 | 第 4、10 课，加上主仓 `docs/runs.md` |
| 会看代码 | 找到工具名、配置默认值、真正执行的函数 | 第 9 课与模板 `src/config.ts`、`src/world.ts` |
| 会写扩展 | 新增一个职责清楚的 World，声明配置和工具，写行为测试 | 主仓 `docs/extensions.md`、`docs/worlds.md`、模板 README |
| 会维护组合 | 验证单装、组合、缺包、关闭联动、重载和版本升级 | 为每种组合保存测试结果，先做小组合再扩大 |
| 能理解框架 | 解释 Core、Persona、Memory、World 的边界与取舍 | 主仓 `PHILOSOPHY.md`、`AGENTS.md`，再读详细框架手册 |

第一次不用背 API。能找到负责这件事的模块、看到真实结果、解释自己的修改，比记住一堆类名更实用。
